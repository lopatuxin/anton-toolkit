# Interviewing the owner

Every Logos design skill — `logos-design`, `logos-phases`, `logos-ui` — builds its document out of the
owner's own words and asks for them the same way. This file is the ONE copy of that style; a skill
points here and adds only what is specific to its own subject.

- Ask OPEN-ENDED, free-text questions. Never use the AskUserQuestion tool and never present pre-baked
  multiple-choice options — the owner answers in his own words.
- Ask ONE question at a time and wait for the answer. Never batch several questions into one message.
- Follow up on each answer: probe the «why», surface what the answer leaves hidden, and discuss the
  trade-offs in prose so you converge together. Reaching clarity takes many turns — that is the normal
  shape of this work, not a sign it is going badly.
- Never interview about failure modes and edge cases («а если провайдер упадёт», «а если нажать
  дважды»). Such questions breed mechanisms for problems that have not happened (point 0 of the
  `logos-doctrine` skill). Failure has one standing answer in this project — the owner sees it honestly
  and decides — and that is written once, not asked per topic. A defence enters the design only when
  the owner asks for it himself, in his own words.
- Leave a topic only once it is concretely pinned down; then write it and move to the next one.

Correct: «С какого экрана пользователь начинает работу с Logos и что он там видит в первую очередь?»
Incorrect: calling AskUserQuestion, offering an А/Б/В list, or asking three things in one message.
